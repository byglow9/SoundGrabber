<objective>
Complete the operator-facing curation surface: add a "Submissões" tab to the Yonkou panel that lists
all submissions and drives edit/promote/publish/reject/archive against the Plan 03/04 endpoints, then
lock in the documentation (SECURITY-CHECKLIST.md + REQUIREMENTS.md traceability) and run a human
verification of the end-to-end flow.

Purpose: This closes the loop from public intake to editorial publish. Because a submitter can put an
XSS payload in a field that later renders in the operator's authenticated browser (which holds the
CSRF token + admin cookie — a high-value target, Pitfall 5), all rendering here must use
escape()/textContent, never innerHTML. This plan is non-autonomous: the final task is a human
checkpoint verifying the visual flow that automated tests cannot cover.
Output: admin tab + docs + human sign-off completing Phase 16.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| submitter-controlled field → operator's authenticated browser | Stored content renders in a session holding the admin cookie + CSRF token |
| operator UI → admin mutation endpoints | Every state change must carry the CSRF token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-02 | Tampering / Elevation of Privilege | Stored XSS via submission field rendered in the admin tab | mitigate | All submission fields rendered via document.createElement + textContent (never innerHTML); server scaffolding uses escape() (Pitfall 5); human check step 9 verifies |
| T-16-07 | Spoofing / Tampering | CSRF on curation mutations from the tab | mitigate | Every promote/publish/reject/archive/edit fetch includes x-csrf-token (SEC-SUBMIT-03) |
| T-16-04 | Information Disclosure | Contact data surfaced outside the admin | mitigate | Contact fields render only inside the auth-gated Submissões tab; no public read path exists; human check step 4 confirms |
| T-16-10 | Repudiation | Undocumented security controls | mitigate | SECURITY-CHECKLIST.md Submissões section documents SEC-SUBMIT-01..05 with verification commands |
</threat_model>
