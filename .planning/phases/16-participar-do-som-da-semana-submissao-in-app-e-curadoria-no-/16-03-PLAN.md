<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → POST /submissions | Unauthenticated write; primary abuse surface |
| operator browser → admin curation routes | Authenticated but CSRF-exposed; session holds high-value cookie |
| path parameter {submission_id} → Redis lookup | Untrusted id string could probe/traverse |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-03 | Denial of Service / Repudiation | POST /submissions spam flooding the queue | mitigate | `@limiter.limit(3/hour per IP)` (SEC-SUBMIT-01) + honeypot silent drop (SEC-SUBMIT-02) + strict Pydantic validation — three layers per D-03 |
| T-16-08 | Elevation of Privilege | Honeypot detection revealed to bots via distinct response/log | mitigate | Filled honeypot returns the identical generic 202 with no distinguishable error or log line |
| T-16-04 | Information Disclosure | Contact data echoed in the public POST response | mitigate | Response returns a fixed generic dict excluding instagram/telefone/email (SEC-SUBMIT-05); no public read endpoint exists |
| T-16-07 | Spoofing / Tampering | Forged admin mutation (edit/reject/archive) via CSRF | mitigate | Every mutation route uses `_admin_csrf_dependency`; GET uses `_admin_required_dependency` (SEC-SUBMIT-03) |
| T-16-06 | Tampering / Information Disclosure | IDOR / traversal via crafted {submission_id} | mitigate | Validate submission_id against JOB_ID_PATTERN before any Redis lookup; 404 on unknown |
| T-16-05 | Denial of Service | Oversized body reaches parsing | mitigate | Existing 4KB `_limit_body_size` middleware applies (no new exception); Plan 02 caps keep legit bodies under it (SEC-SUBMIT-04) |
</threat_model>
